- **`configuration_run.get_configuration_run_measurement`: the stored measures of a configuration run, read as one bounded page (additive).** `GET /api/v1/projects/{project_id}/configuration-runs/{configuration_run_ref}/measurement` returns the new `execution/configuration_run_measurement_response_schema.json`: `data.shape` is `flat` (a map of measure names to numbers or null in `measures`) or `per_example` (a cursor page of `items`; each item is either a `MeasurementItem` with `example_id` and metrics, or a bare metric map from the older stored form that has no `example_id`; metric values may be null), with `pagination` (`limit` default and maximum 100, `next_cursor`, `has_more`, `total`). Query: `limit` and `cursor`. The cursor is sealed and opaque; a cursor is invalidated when the stored results change, and a stale one is the closed 400 `invalid_cursor`. Path parameters are as for the other configuration-run operations.
- **`configuration_run.get_configuration_run_status`: the status of a configuration run on its own reference (additive).** `GET /api/v1/projects/{project_id}/configuration-runs/{configuration_run_ref}/status` returns the new `execution/configuration_run_status_response_schema.json`: `data.status` (the shared configuration-run status) and `data.error_message` (string or null, any length the update accepts), with a fixed success message. It replaces the run-owned status read. The 404 is the closed `NotFoundProblem`, identical for a missing, foreign or ungranted configuration run. Path parameters are as for the other configuration-run operations. The optional query parameter `expected_run_ref` (an experiment run reference) makes a configuration run that does not belong to that experiment run answer the same closed 404 as an absent one.
