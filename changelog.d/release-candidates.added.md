- **Release candidate API contract.** Clients can report a promotion gate verdict and its digests for an agent's best-config version. The portal can list and read those records to prefill a person's release acceptance. The agent detail response (`GET /api/v1/projects/{project_id}/agents/{agent_ref}`, 200 `data`) gains an optional `agent_ref`: the server-issued release reference (`AgentRef`, `opaque_ref`) that the release-acceptance and release routes take in their `{agent_ref}` segment. It is defined by the new `agents/agent_detail_schema.json`, which references each property of `agent_schema.json` by pointer, so the shared `agent_schema.json` and the other endpoints that use it are unchanged. The release-family `agent_ref` path parameters now name where a portal reads the reference.
