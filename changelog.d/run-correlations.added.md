- **`experiment_run.get_run_correlations`: run correlations declared on an experiment-run reference; the analytics-path GET deprecated (additive, contract only).** `GET /api/v1/projects/{project_id}/experiment-runs/{experiment_run_ref}/correlations` (operation id `experiment_run.get_run_correlations`) takes the server-issued reference `^experiment_run_[0-9a-f]{32}$` and the explicit project, and the backend's real query parameters: `method` (`pearson`/`spearman`, default `pearson`) and `min_sample` (integer 2 to 10000, default 3). The 200 is the new `analytics/experiment_run_correlations_response_schema.json`, a closed definition of the fields the correlations computation always emits (`method`, `sample_size`, `measure_correlations`, `parameter_correlations`, `warnings`); `data.run_id` is omitted (internal id) and rejected by the closed schema. Dimensions and input are bounded: at most 128 numeric measure dimensions (8128 measure pairs) and 128 numeric parameter dimensions (16384 parameter-measure rows; the backend accepts 100 search-space parameters; booleans count, string-valued parameters are excluded), counted on the exact normalized inputs after authorization and before either analysis loop, with the required `meta.measure_dimensions_total` and `meta.parameter_dimensions_total`. The input budget is the Pareto contract's: a work cap of 10000 scoped configuration rows counted during the scoped read before materialization, and `sample_size` is the exact measured-configuration count (at most 10000). Non-numeric (categorical, string-valued) parameters are excluded before the importance loop, because the backend scans every stored parameter key per measure before omitting categorical ones, and the number of distinct stored parameter keys across the run's configurations is capped at 256, with the closed 503 above it (never truncated), counted with the other caps before any analysis loop. A run over either limit, or a stored measure or parameter name that fails the name pattern (a control character such as a tab, or a length over 256; never truncated or sanitized, since that could merge two names), is the closed 503 (the backend does not enforce these limits today; backend obligation). Names are 1 to 256 characters of `[^\x00-\x1f\x7f]`, and every name and warning pattern ends with `$`; `warnings` are constrained to the builder's three formats as patterns, at most 8129 of at most 534 characters. `r` and `effect` are bounded to [-1, 1]. The canonical handler parses the query strictly (unknown and tenant-selector keys are the closed 400), unlike the legacy adapter. The 1 MiB limit (`x-max-response-bytes` 1048576) is enforced on the serialized envelope, with the closed 503 over the limit and no static byte bound in the schema. Errors are the closed problems of `analytics/correlations_problem_schema.json` (400 malformed reference or rejected query value, naming and echoing nothing; 401, 403, one identical 404, 429, 500, 503). `GET /api/v1/analytics/runs/{run_id}/correlations` stays declared, marked `deprecated` and naming the successor; its project-scoped beta mount is not declared here and retires with it. `run_correlations_schema.json` and `run_correlations_response_schema.json` are unchanged. Removal follows the backend retirement PR after the client receipt.
