- **`experiment_run.get_run_pareto`: run Pareto analysis declared on an experiment-run reference, paginated; the analytics-path GET deprecated (additive, contract only).** `metrics` keys use the shared measure-name class `^[^\x00-\x1f\x7f]{1,100}$` (the same as `x_measure` and `y_measure`, so names such as `review score` are valid); a stored metric name outside it makes the run's response the closed 503, never truncated or sanitized. The shared `trial_ref` accepts both issued formats, `trial_` plus 16 hex and `configuration_run_` plus 32 hex; every pattern in the report and Pareto schemas and in their query and path parameters ends in `$` (not the absolute end `(?![\s\S])`, because Pydantic v2's rust-regex engine refuses lookahead; trailing-newline hardening is applied by the Python-side validators). The cursor seals caller, project, run, query and `analysis_revision` (a per-run monotonic counter the backend increments in the same transaction as any insert or delete of the run's configuration rows and any update that changes a configuration row's analysis content); a stale or foreign cursor is the closed 400 `invalid_cursor` (declared in the problem schema). Frontier ties break by ascending `trial_ref` (lexicographic) before ranks are assigned; dominated entries are ordered by ascending `trial_ref` (lexicographic). The 10000 cap counts ALL scoped configuration rows before any metric processing (above it the closed 503). Metric values are any finite JSON number (the earlier 1e15 bound is removed). `has_more` is true if and only if `next_cursor` is non-null. `warnings` are constrained to the builder's three tag forms. The deprecation names the full beta route `/api/v1beta/projects/{project_id}/analytics/runs/{run_id}/pareto`. `GET /api/v1/projects/{project_id}/experiment-runs/{experiment_run_ref}/pareto` (operation id `experiment_run.get_run_pareto`) takes the server-issued reference `^experiment_run_[0-9a-f]{32}$` and the explicit project. Query: `limit` (default 20, maximum 100), `cursor` (opaque sealed string, at most 512 base64url characters, bound to caller, project, run and query), and the backend's own `x_measure`, `y_measure` (1-100 characters, defaults `cost` and `quality`) and `request_count` (1 to 1000000, default 1) from the backend's query; every other parameter, including retired `page` and `offset`, is the closed 400. The 200 is the new `analytics/experiment_run_pareto_response_schema.json`: `data` carries `run_id` (the experiment_run_ref), `measures`, `shape`, `knee_ref`, `frontier_total`, `dominated_total`, `warnings`, `items` and `pagination` (`limit`, `next_cursor` nullable, `has_more` and a required integer `total`), mirroring the backend Pareto computation. The ranking, frontier, knee and shape are computed over the full eligible population (at most 10000 configurations; more is the closed 503) and only then paginated, ordered frontier first by ascending rank then dominated, with ascending `trial_ref` (lexicographic) as the stable tie-breaker; the historical 500/1000 truncation is replaced by pagination. At most 100 items per page, metrics at most 5 names. The 1 MiB limit (`x-max-response-bytes` 1048576) is enforced on the serialized envelope: the handler measures the final serialized bytes, sends those same bytes, and returns the closed 503 over the limit; the schema gives no static byte bound. Canonical projection omits config_id: internal configuration-run id (replaced by the run-scoped `trial_ref` of `analytics/experiment_run_trial_ref_schema.json`, `^(trial_[0-9a-f]{16}|configuration_run_[0-9a-f]{32})$`: `trial_ref` is the configuration run's issued public reference (sessions issue trial_ plus 16 hex, an issued reference is never re-minted, unique per tenant, NULL until the reference backfill). Two issued formats exist: trial_ plus 16 hex (issued by sessions) and configuration_run_ plus 32 hex (minted by the backend). Issued once, never re-minted, so it is stable across views, pages and deletion of other configurations. The internal id is never emitted. A canonical view of a run with any configuration whose reference is not yet issued is the closed 503 until the backfill completes (never a positional or synthetic stand-in)). Canonical projection omits project_id: the explicit URL project. Canonical projection omits run_id as a historical id: `data.run_id` is the experiment_run_ref. `dominated_by` is a `trial_ref`, never an internal id. The closed schema rejects these properties. Errors are the closed problems of `analytics/pareto_problem_schema.json` (400 malformed reference, limit or query echoing no value, and the closed `invalid_cursor` 400 for any invalid or stale cursor, 401, 403, one identical 404, 429, 500, 503). `GET /api/v1/analytics/runs/{run_id}/pareto` stays declared, marked `deprecated` and naming the successor; its project beta mount retires with it. `run_pareto_schema.json` and `run_pareto_response_schema.json` are unchanged. Removal follows the backend retirement PR after the client receipt.
