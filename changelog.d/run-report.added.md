- **`experiment_run.get_run_report`: run report declared on an experiment-run reference; the analytics-path GET deprecated (additive, contract only).** `GET /api/v1/projects/{project_id}/experiment-runs/{experiment_run_ref}/report` (operation id `experiment_run.get_run_report`) takes the server-issued reference `^experiment_run_[0-9a-f]{32}$` and the explicit project, with no query parameters. The 200 is the new `analytics/experiment_run_report_response_schema.json`, a closed definition that declares every field the report builder always emits (`generated_at`, `experiment_context`, `methodology`, `example_index_map`, `provenance` with `source_counts`, `max_source_timestamp`, `generator_versions`, rows, insights, warnings). The serialized response is the authority for the 8 MiB limit (`x-max-response-bytes` 8388608); the schema gives no static byte bound. The handler measures the final serialized envelope, sends those same bytes, and returns the closed 503 over the limit. Collection caps are realistic limits: 1000 aggregated rows, 5000 raw example rows (`example_index_map` indexes the displayed rows only), 50 insights computed over the full population, 1000 warnings of at most 512 characters, labels 512 characters. Rows beyond a cap are truncated server-side; `meta.aggregated_results_total` and `meta.raw_example_results_total` (both required integers) carry the untruncated counts. `config_params` follows the sanitizer shapes: depth 3, lists of at most 12 items, strings of at most 128 characters, at most 64 keys per object. `data.provenance.run_id` is required and is the experiment_run_ref (the projection populates it from the resolved reference). Row identity is the opaque run-scoped `trial_ref` (`^(trial_[0-9a-f]{16}|configuration_run_[0-9a-f]{32})$`, defined once in the new `analytics/experiment_run_trial_ref_schema.json` shared with the Pareto view; `trial_ref` is the configuration run's issued public reference (sessions issue trial_ plus 16 hex, an issued reference is never re-minted, unique per tenant, NULL until the reference backfill). Two issued formats exist: trial_ plus 16 hex (issued by sessions) and configuration_run_ plus 32 hex (minted by the backend). Issued once, never re-minted, so it is stable across views, pages and deletion of other configurations. The internal id is never emitted. A canonical view of a run with any configuration whose reference is not yet issued is the closed 503 until the backfill completes (never a positional or synthetic stand-in); shared by aggregate and example rows). `trial_ref` is the persisted configuration_run_ref, not a positional index; `trial_id` (the internal configuration-run id) is rejected. The projection must also scrub internal ids embedded in warnings, insight evidence and fallback labels (backend obligation). Canonical projection omits experiment_context.experiment_id: internal id. Canonical projection omits experiment_context.run_id: internal id. Canonical projection omits provenance.source_endpoints: URLs embed the internal run id. Canonical projection omits report_id: it embeds the internal run id. Canonical projection omits trial_id: internal configuration-run id (replaced by trial_ref). The closed schema rejects these properties. Errors are the closed problems of `analytics/report_problem_schema.json` (400 malformed reference, 401, 403, one identical 404, 429, 500, and 503 when the serialized report is over the limit or cannot be produced, never a partial success). `GET /api/v1/analytics/runs/{run_id}/report` stays declared, marked `deprecated` and naming the successor; its two beta mounts are not declared here and retire with it. The optimization report payload (`report.get_optimization_report_payload`) is a separate contract and unchanged. Removal follows the backend retirement PR after the client receipt.
