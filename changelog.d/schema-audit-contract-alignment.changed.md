- **`promotion_policy_schema.json` per-schema version 0.10.0 to 0.11.0** for the #580 constraint tightening below.
- **Annotation-queue and evaluator update bodies need one usable field (BREAKING for clients that sent only a null description, or, on annotation queues, only a blank name or description; the service already refused these with 422) (#723).** `annotation_queue_update_request_schema.json` and `evaluator_update_request_schema.json` gain a root `anyOf`, and an empty body is refused by both. On annotation queues, a body whose only field is a null description, a blank name or a blank description is refused. On evaluators, a body whose only field is a null description is refused; a blank name or description is still accepted by the schema and the backend, which has no strip validator. Both update schemas are referenced via `$ref` from `observability_endpoints.json`.
- **Non-breaking: evaluator update accepts an explicit `null` for `target_type` (#723).** `target_type` is nullable in `evaluator_update_request_schema.json` and `null` means unchanged, matching `EvaluatorDefinitionUpdateRequest` in the backend. A body with another field and a null `target_type` is accepted; a body whose only field is a null `target_type` is refused, as the service refuses it.
- **Tighter request validation (breaking for clients that used the older schema allowances).**
  `promotion_policy`: `alpha` in (0, 1), `min_effect` values >= 0, chance-constraint `threshold` in [0, 1], `confidence` in (0, 1) (#580).
  Evaluators: the update and execute request bodies are closed (unknown keys are refused); update drops `primary_measure_id`, needs at least one property and declares `target_type`; execute drops `source`; the backfill body is the new closed `evaluator_backfill_request_schema.json` (`target_type`, `filters`, `limit`, `skip_existing_scores`; `target_ids` and `force` removed) (#584).
  Annotation queues: the create and update bodies are closed, and `description` is at most 2000 characters before trimming. The backend trims first, so the schema can reject a padded value the service accepts. An update needs at least one property; a body whose only fields are null, or that has only blank name or description, is refused by the schema (#640, #645, #723).
  Prompts: `prompt_text` at most 10000 characters before trimming in the three prompt request schemas. The backend trims first, so the schema can reject a padded prompt the service accepts (#650).
  Example-set create: `selection_method` and `type` are enums, `tags` at most 100 (#671).
- **Finalize and backfill accept an explicit `null`.** `optimization_outcome` may be `null` on the session finalize request, meaning absent (completed). `target_type` may be `null` on the evaluator backfill request, meaning the evaluator's own target type.
- **Non-breaking: agent create `retrieval_configs` and `model_parameters` allow up to 100 items (was 50), matching the backend cap (#652).** This loosens the schema; no request the service accepts is refused.
- **Identity: `compute_agent_build_digest` now rejects a present `source_digest` that is not `sha256:<64 hex>`, including for dirty builds (#697).**

- **Evaluator backfill result declares `skipped_reasons` and `skipped_reason_counts` (#648). These optional fields constrain values previously accepted as undeclared extensions.** Legacy run-analytics GET endpoints declare their query parameters (`objective`, `limit`, `request_count`, ...) (#641). The project-scoped replacements keep their existing query contracts. The session finalize request declares `optimization_outcome` (`completed`, `failed`, `cancelled`) (#696).
